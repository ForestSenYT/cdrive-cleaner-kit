# 任务：实现轻量版 C 盘清理

在当前工程里实现一个 Windows 磁盘清理功能：按规则文件只读扫描出可清理的文件，报告数量和大小，用户确认后永久删除。实现语言、目录结构和界面形式跟随当前工程。行为定义、默认规则和验收工具都在资源包 `cdrive-cleaner-kit/` 里。

## 资源包

| 文件 | 内容 | 什么时候用 |
|---|---|---|
| `SPEC.md` | 行为的唯一定义 | 动手前通读 |
| `rules/rules.json` | 默认规则集，原样随产品发布 | 实现规则加载时 |
| `rules/rules.schema.json` | 规则文件结构（JSON Schema 2020-12） | 校验或编辑规则时 |
| `reference/cleaner_ref.py` | 参考实现，Python 3 标准库 | `SPEC.md` 对某个边界情况说得不够清楚时，运行或阅读它 |
| `conformance/run_conformance.py` | 验收工具 | 每个步骤结束时 |
| `original/rules.xml`、`original/README.md` | 被分析软件的原始规则表（71 条）和它的格式说明，属于参考资料 | 用户要求扩充规则集时，按说明把条目翻译进 `rules/rules.json`；实现本任务的六个步骤不需要读它 |

验收工具需要 Windows 上的 Python 3.8 或更高版本，只用标准库。`--tool` 是被测程序的命令前缀，工具会在它后面追加 `scan ...` 或 `clean ...` 参数；`--only load|scan|clean` 只跑其中一组。

## 安全边界

整个开发过程中：

- `clean` 只对验收工具自己生成的 fixture 目录运行。对真实系统只运行 `scan`，真实清理留给用户本人触发。
- 回收站的清空逻辑只实现，不执行。

## 步骤

1. **定位**。通读 `SPEC.md`，查看当前工程的语言、构建方式和已有的命令行或界面入口，确定清理模块和命令行入口放在哪里。
   完成标准：能写出运行 `scan` 的完整命令行，并确定了调用 `CreateFileW`（指定共享模式）和 `SHQueryRecycleBinW` 的方式。当前工程是空的或技术栈不明确时，先向用户确认语言和产品形态。

2. **规则加载**（`SPEC.md` 第 2 节）。
   完成标准：`python conformance/run_conformance.py --tool "<命令前缀>" --only load` 全部 PASS。

3. **扫描**（第 3 到 6 节，第 8 节的 `scan`）。
   完成标准：`--only scan` 全部 PASS。再用 `rules/rules.json` 对真实系统各跑一次本实现和参考实现的 `scan --json`，逐条规则比较 `files`；每一处差异要么消除，要么能指出是哪些文件、为什么不同（两次扫描之间文件会变化）。

4. **清理**（第 7 节，第 8 节的 `clean`）。
   完成标准：不带 `--only` 运行验收工具，全部 PASS。

5. **接入**。把扫描和清理接到工程现有的界面或调用方：规则按 `group` 分组展示，初始勾选取 `default_selected`，展示 `note` 和 `risk`，清理前要求用户确认，清理后展示每条规则删除了多少、失败了多少。
   完成标准：通过界面完成一次"扫描、勾选、确认、清理 fixture 目录"的完整流程。工程只有命令行时跳过这一步。

6. **汇报**。给出：验收工具的最终输出；真实扫描的汇总；`SPEC.md` 和参考实现之间发现的任何不一致；没有验证的部分，至少包括回收站清空。
