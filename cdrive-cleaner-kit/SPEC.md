# 轻量版 C 盘清理：行为规范（规则格式 1）

本文件是行为的唯一定义。`reference/cleaner_ref.py` 是它的可运行对照；两者不一致时以本文件为准，并把不一致报告出来。

## 0. 范围

- **做什么**：读取规则文件；只读扫描出可清理的文件，报告数量和大小；用户选择规则并确认后，永久删除扫描到的文件；统计和清空系统盘回收站。
- **不做什么**：注册表清理、组件存储和更新卸载清理、第三方软件专用规则、大文件搬家、隐私清理、联网、账号、开机自启。
- **来源**：整体流程参考了对一款商业清理软件的静态分析，该分析没有做运行验证。规则集和安全约束是重新设计的，差异列在第 9 节。本资源包不含该软件的代码；`original/` 下附有它的规则表原文，只作参考，本规范定义的程序不加载它。

## 1. 术语

| 术语 | 含义 |
|---|---|
| 规则 | 规则文件里的一项，用户以规则为单位勾选 |
| 目标 | 规则里的一个 `{root, include, exclude}` |
| 根 | 目标的 `root` 展开后得到的具体目录，一个目标可以展开出零到多个根 |
| 模式 | `include` / `exclude` 里的一个相对路径 |
| 段 | 路径中两个分隔符之间的部分 |
| 重解析点 | 带 `FILE_ATTRIBUTE_REPARSE_POINT` 属性的文件或目录（符号链接、目录联接等） |
| 受保护目录 | 第 4 节列出的、不允许被整体清理的目录 |

## 2. 规则文件

UTF-8 编码的 JSON，结构见 `rules/rules.schema.json`。路径里 `/` 和 `\` 等价，规则文件统一写 `/`。

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 顶层 | `format` | 是 | 必须为 `1` |
| 顶层 | `rules` | 是 | 规则数组，顺序有意义（见第 5 节） |
| 顶层 | `$schema` | 否 | 仅供编辑器使用 |
| 规则 | `id` | 是 | 小写字母、数字、连字符，以字母或数字开头，全文件唯一 |
| 规则 | `name`、`group` | 是 | 展示名称和分组 |
| 规则 | `kind` | 是 | `files` 或 `recycle_bin` |
| 规则 | `description`、`note` | 否 | 说明文字；`note` 是需要让用户看到的后果提示 |
| 规则 | `risk` | 否 | `low`（默认）或 `medium` |
| 规则 | `default_selected` | 否 | 界面初始是否勾选，默认 `false` |
| 规则 | `min_age_hours` | 否 | 仅 `files`，数值且不小于 0 |
| 规则 | `targets` | `files` 必填 | 非空数组；`recycle_bin` 规则不允许出现 `targets` 和 `min_age_hours` |
| 目标 | `root` | 是 | 见下 |
| 目标 | `include`、`exclude` | 否 | 模式数组 |

以下任一情况成立时**整份规则文件被拒绝**（退出码 2，不做任何扫描）：

- 不是合法 JSON，或不符合上表。
- 出现上表之外的字段。拼错的 `exclude` 如果被悄悄忽略，删除范围会变大，所以未知字段一律拒绝。
- `root` 的任何一段为空、`.` 或 `..`；或第一段既不是盘符（如 `C:`）也不以 `%` 开头；或第一段含 `*`。
- 模式的任何一段为空、`.` 或 `..`（因此模式不能以分隔符开头）；或模式里含 `:` 或 `%`。

## 3. 根的展开

对每个目标的 `root` 依次执行：

1. **环境变量**。`%NAME%` 可以出现在任意位置，用进程环境变量替换，变量名不区分大小写。只要有一个变量未定义，跳过这个目标并给出警告 `unresolved_variable`。
2. **形式检查**。替换后必须是 `X:\...` 形式的绝对路径，且没有空段、`.`、`..`；否则跳过并警告 `invalid_root`。
3. **逐段解析**，从盘符根目录开始：
   - 不含 `*` 的段：必须是已存在的目录，否则这条分支到此结束且不警告（目录不存在是正常情况）。如果它是重解析点，分支结束并警告 `reparse_point_in_root`。
   - 含 `*` 的段：枚举当前目录的直接子目录，保留名称匹配且不是重解析点的。被跳过的重解析点不警告。

**通配符**只有 `*`：匹配一个段内任意长度（含零）的任意字符，不匹配路径分隔符；其余字符按字面比较；比较不区分大小写。没有 `?`、`[]`、`**`。

## 4. 目标解析

对每个根，求出它选中的文件集合：

- `include` 为空：根目录下的全部文件（递归）。
- `include` 非空：对每个模式，前面的段逐级匹配子目录，最后一段匹配文件或目录。匹配到文件就取该文件；匹配到目录就取其下全部文件（递归）。各段都按第 3 节的通配符规则匹配名称，重解析点一律不匹配。
- **递归遍历**不进入重解析点目录，也不报告重解析点文件；读不了的目录按空目录处理。
- **排除**：把文件相对根的路径拆成段。某个 `exclude` 模式有 n 段，而文件路径的前 n 段与它逐段匹配，则该文件被排除。也就是说，模式命中文件本身或它的任一上级目录都算。排除模式数量不限。

**受保护目录**：任意盘的根目录；`%SystemRoot%` 及其下的 `System32`、`SysWOW64`、`WinSxS`；`%ProgramFiles%`、`%ProgramFiles(x86)%`、`%ProgramW6432%`、`%ProgramData%`；`%USERPROFILE%`、`%APPDATA%`、`%LOCALAPPDATA%`；`%SystemDrive%\Users`。比较时忽略大小写和结尾分隔符。

- 将要被递归遍历的目录本身是受保护目录：不遍历，警告 `protected_root`。
- 根是受保护目录，且模式的每一段都只由 `*` 组成：跳过该模式，警告 `protected_root`。

受保护目录下的具体子目录和具体模式不受影响，例如 `%SystemRoot%` 配 `*.log` 是允许的。

## 5. 归属、过滤和统计

规则按文件中的顺序处理。

1. **归属**。一个文件属于第一条选中它的规则（被 `include` 命中且未被 `exclude` 排除）。后面的规则不再报告它，即使第一条规则的过滤器把它筛掉了。这样总量不会重复计算，靠后的规则也绕不过靠前规则的年龄限制。
2. **年龄过滤**。规则有 `min_age_hours` 时，最后修改时间距现在不足该小时数的文件被跳过，计入 `skipped.too_new`。
3. 通过的文件计入该规则的 `files` 和 `bytes`（文件逻辑大小之和，单位字节），并记入该规则的文件清单。

扫描全程只读，不创建、修改或删除任何东西，也不打开任何文件：是否被占用留到清理时逐个判断（第 7 节）。因此扫描报告的是候选文件，其中正被占用的少数文件会在清理时跳过并报告。

## 6. 回收站规则

`kind` 为 `recycle_bin` 的规则只针对系统盘（`%SystemDrive%`）。

- **扫描**：`SHQueryRecycleBinW(系统盘根目录, &info)`，`files` 取 `i64NumItems`，`bytes` 取 `i64Size`。调用失败时两者为 0 并警告 `recycle_bin_query_failed`。
- **清理**：`SHEmptyRecycleBinW(NULL, 系统盘根目录, SHERB_NOCONFIRMATION | SHERB_NOPROGRESSUI | SHERB_NOSOUND)`。报告里的数量和字节数用清空前查询到的值。
- `SHQUERYRBINFO` 在 32 位构建中按 1 字节对齐（`cbSize` 为 20），在 64 位构建中为 24。

## 7. 清理

- 只在用户显式选定规则并确认后执行。
- 删除对象是本次扫描得到的、所选规则的文件清单，不重新匹配规则。
- 对清单里的每个文件，删除前依次复查，任何一步不通过就跳过并记录错误码：

  | 检查 | 错误码 |
  |---|---|
  | 文件仍然存在 | `gone` |
  | 是普通文件，不是目录，也不是重解析点 | `not_regular_file` |
  | 占用探测通过 | `in_use_or_denied` |
  | 永久删除成功（等价于 `DeleteFileW`） | `delete_failed` |

- **占用探测**：以只读方式、只允许共享读打开文件，`CreateFileW(path, GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL)`，打开成功即通过并立刻关闭。打不开说明有其他进程正以写方式打开它，或当前账户没有权限。对方即使允许共享删除，这个文件也不删。
- 不删除任何目录，不修改文件属性，不安排重启后删除，不重试。

## 8. 命令行契约

验收工具通过下面的命令行驱动实现。图形界面产品可以不向最终用户暴露它，但需要保留一个等价入口。

```
<tool> scan  --rules <file> [--json] [--list]
<tool> clean --rules <file> --select <id>[,<id>...] --yes [--json]
```

- 退出码 `0`：命令执行完成，包括带警告或有文件删除失败的情况。
- 退出码 `2`：规则文件被拒绝、参数错误、`--select` 含未知的规则 id、`clean` 缺少 `--yes`。此时不扫描、不删除。
- `--json` 时标准输出是一个 UTF-8 JSON 文档；错误信息写到标准错误。
- `clean` 在同一进程内先扫描、再删除所选规则的文件清单。

`scan --json` 的输出，规则顺序与规则文件一致；`paths` 只在 `--list` 时出现，是绝对路径：

```json
{
  "format": 1,
  "rules": [
    {
      "id": "user-temp",
      "kind": "files",
      "files": 2,
      "bytes": 300,
      "skipped": { "too_new": 1 },
      "warnings": [{ "code": "unresolved_variable", "target": 0, "detail": "NAME" }],
      "paths": ["C:/..."]
    }
  ],
  "total_files": 2,
  "total_bytes": 300
}
```

`warnings[].target` 是目标在规则里的序号，回收站规则为 `null`。警告码：`unresolved_variable`、`invalid_root`、`reparse_point_in_root`、`protected_root`、`recycle_bin_query_failed`。

`clean --json` 的输出，只包含所选规则：

```json
{
  "format": 1,
  "rules": [
    {
      "id": "user-temp",
      "kind": "files",
      "deleted_files": 2,
      "deleted_bytes": 300,
      "failed": [{ "path": "C:/...", "error": "in_use_or_denied" }]
    }
  ],
  "total_deleted_files": 2,
  "total_deleted_bytes": 300
}
```

## 9. 与被分析程序的差异

左列来自静态分析，没有运行验证。

| 被分析程序 | 本规范 | 原因 |
|---|---|---|
| 规则文件加密，文件名伪装成别的资源 | 明文 JSON | 可审计 |
| 清理前检查付费权益，安装和使用上报统计 | 没有 | 范围外 |
| 规则带适用条件，但组合条件和系统版本条件被忽略，规则实际比作者设想的宽 | 没有条件系统，路径不存在自然没有结果 | 简化 |
| 排除项只在恰好一条时生效 | 条数不限 | 修正缺陷 |
| 变量只在路径开头展开，变量未知的规则被悄悄丢弃 | 任意位置展开，未知变量给出警告 | 可诊断 |
| 属性查询失败的路径也被当成目录继续处理 | 必须确认是已存在的目录 | 修正缺陷 |
| 递归遍历怎样处理重解析点没有确认 | 一律不进入 | 防止删到规则范围之外 |
| 没有受保护目录 | 有 | 防止规则写错 |
| 没有文件年龄条件 | `min_age_hours` | 避免删掉刚生成、仍在使用的临时文件 |
| 扫描时对每个文件做占用探测（只读加共享读打开），打不开就不计入 | 同样的探测，只在删除前做 | 实测见第 10 节：逐个探测让扫描从约 2 秒变成约 6 分钟，而被占用的文件只有十个左右 |
| 同一文件可被多条规则重复计入 | 归属第一条规则 | 总量准确 |
| 大小按 KB 累计 | 字节 | 精度 |
| 逐个 `DeleteFileW`，不看返回值 | 删除前复查，逐个报告结果 | 可靠 |
| 回收站遍历一个盘符列表 | 仅系统盘 | 范围 |
| 读注册表的路径宏、按版本号识别旧版本目录、调用系统组件清理过程 | 不支持 | 轻量 |

## 10. 实现注意

- **64 位进程**。32 位进程访问 `System32` 会被重定向到 `SysWOW64`，规则里的路径会指错地方。
- **长路径**。长度达到 248 个字符的路径要用扩展长度路径前缀，或启用系统的长路径支持。
- **权限**。不需要管理员权限也能运行，没有权限的目录读作空目录；以管理员身份运行能覆盖更多系统目录。
- **探测通过不等于删得掉**。只读属性或只允许读取的访问控制会让删除失败，这类文件计入 `failed`。
- **规则文件是受信任输入**，随产品发布。受保护目录用来防止规则写错，不是安全边界。
- **扫描只做目录枚举**，直接使用枚举返回的属性、大小和修改时间，不对单个文件再做查询或打开。参考实现在一台临时目录约有 8.6 万个文件的机器上，枚举用时约 2 秒；对其中 7.2 万个文件逐个打开探测则需要约 6 分钟，平均每次打开约 5 毫秒。
- **清理按分钟计**。清理时每个文件都要打开，文件多时需要几分钟：显示进度，允许中途取消，已删除的文件不回滚。
- **可选优化，参考实现没有采用**：把探测和删除合并成一次打开，即以读加删除权限、只允许共享读打开文件，再对句柄设置删除标记。采用前用验收工具确认行为不变。
